# pdns-r53-sync

Mirrors one public zone from PowerDNS to AWS Route53. The zone is read through the
[Poweradmin](https://github.com/poweradmin/poweradmin) API v2 (the only thing the cluster
needs to reach) and written with [octoDNS](https://github.com/octodns/octodns).

```
Poweradmin API v2 (HTTPS, X-API-Key)
      │  every pollInterval s: GET /api/v2/zones/{id}/records?type=SOA → serial
      ▼
pdns-r53-sync (exactly 1 pod)
      │  serial changed  → octoDNS sync Poweradmin → Route53
      │  every fullSyncInterval s → sync anyway (reverts manual edits in Route53)
      ▼
Route53 public hosted zone (registrar NS unchanged)
```

Poweradmin/PowerDNS is the single source of truth; Route53 is a mirror.

## Safety rails

| Rail | Where |
|---|---|
| One pod, `Recreate`, no replicas value, no HPA | Deployment template, values schema rejects unknown keys |
| Dry-run by default; only an explicit `sync.dryRun=false` writes | values, zone `always-dry-run`, app default |
| NS never published (root NS stay `awsdns-*`), DS and glue skipped | source + `TypeRejectlistFilter` + `IgnoreRootNsFilter` |
| Private/special A/AAAA never published (RFC 1918, CGNAT, loopback, link-local, ULA) | hard-coded filter; values can only add networks |
| Change thresholds: update ≤ 0.3, delete ≤ 0.2, never forced | values schema + app refuses looser config |
| Writes only to the pinned hosted zone; never creates one | pre-sync guard (`route53.hostedZoneId` must be the only public zone of that name) |
| Route53-only records survive: alias records (CloudFront, ALB, ...) and ACM validation CNAMEs (`_<32 hex>`) | `filters.ignoreRoute53Aliases`, `filters.ignoreAcmValidation` (both default on, both sides) |
| Records that octoDNS finds unusual (e.g. SRV `dc._msdcs`) are mirrored as-is, never dropped (dropping = deleting in Route53) | source, `pa_sync_lenient_records` |
| Dot-less targets already in Route53 (`www.example.com` from Terraform's `.fqdn`) count as FQDNs, not as updates | `TargetFqdnNormalizer` on the Route53 side |
| Secrets only as files from a Secret, never in values/env/ConfigMap | `secretEnv.existingSecret` |

Filters apply to both sides, so records Route53 already has that match them
(e.g. a private A record or a delegation NS created by hand) are left untouched rather than deleted.
A plan refused by a threshold is still logged in full; resolve it by fixing the data, not by forcing.

## Preparing Poweradmin

1. Enable the API (`api.enabled = true` in `settings.php`, or `PA_API_ENABLED=true` when settings
   are generated by the container). Poweradmin 4.2.x is required (API v2).
2. Create a dedicated user, e.g. `r53-sync`, with the **Viewer** permission template
   (`zone_content_view_own`) and make it an owner of the zone to mirror (directly or via a group).
   Poweradmin API keys cannot be restricted per zone or to read-only; a key has exactly the
   permissions of its user, so keep that user minimal.
3. Log in as that user and create an API key.

Check from the cluster (does not print the key):

```bash
kubectl -n dns run pa-check --rm -it --restart=Never --image=curlimages/curl -- \
  curl -s -o /dev/null -w '%{http_code}\n' -H "X-API-Key: $KEY" "$PA_URL/api/v2/zones?name=example.com"
```

`200` = OK, `401` = bad key, `403` = API disabled.

Every poll is one API request and one `last_used_at` update in the Poweradmin database
(~17k/day at the default 5 s). Raise `sync.pollInterval` to 10–15 if that matters.

## Preparing AWS

The hosted zone must already exist. IAM policy for the sync user (or IRSA role):

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["route53:ListHostedZones", "route53:ListHostedZonesByName", "route53:ListHealthChecks"],
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": ["route53:GetHostedZone", "route53:ListResourceRecordSets"],
      "Resource": "arn:aws:route53:::hostedzone/ZONE_ID"
    },
    {
      "Effect": "Allow",
      "Action": "route53:ChangeResourceRecordSets",
      "Resource": "arn:aws:route53:::hostedzone/ZONE_ID",
      "Condition": {
        "ForAllValues:StringNotEquals": { "route53:ChangeResourceRecordSetsRecordTypes": ["NS", "SOA"] }
      }
    }
  ]
}
```

`CreateHostedZone` is deliberately absent.

## Secrets

Create one Secret (External Secrets, sealed-secrets or by hand). Keys named like the env vars need
no mapping:

```bash
kubectl -n dns create secret generic dns-sync-example \
  --from-literal=POWERADMIN_API_KEY=... \
  --from-literal=AWS_ACCESS_KEY_ID=... \
  --from-literal=AWS_SECRET_ACCESS_KEY=...
```

Other key names: `secretEnv.existingSecretKeys: {POWERADMIN_API_KEY: <key>, ...}`.
With IRSA / EKS Pod Identity set `route53.credentials: ambient` and annotate the service account;
then only `POWERADMIN_API_KEY` is needed.

`secretEnv.values` exists for tests only: values end up in the Helm release history.

## Install

```yaml
# values-<cluster>.yaml — no secrets in here
zone: example.com
poweradmin:
  url: https://poweradmin.example.net
route53:
  hostedZoneId: Z0123456789ABCDEFGHIJ
secretEnv:
  existingSecret: dns-sync-example
sync:
  dryRun: true
```

```bash
helm repo add sortns_charts https://sortns.github.io/helm
helm upgrade --install dns-sync sortns_charts/pdns-r53-sync -n dns -f values-<cluster>.yaml
kubectl -n dns rollout status deploy/dns-sync-pdns-r53-sync
kubectl -n dns exec deploy/dns-sync-pdns-r53-sync -- python -m pa_sync check
kubectl -n dns logs deploy/dns-sync-pdns-r53-sync | grep -E 'plan:|sync reason|ERROR'
```

`check` verifies the config, Poweradmin access (zone id, serial, record counts, every skipped record
with the reason) and the hosted zone guard. `python -m pa_sync plan` prints a fresh plan and never
applies it, whatever the mode.

Review the dry-run plan before going live:

- `plan: Delete ...` — exists in Route53 but not in Poweradmin. Add it to Poweradmin first, or it
  will be removed.
- `plan: Update ...` — Route53 differs from Poweradmin; Poweradmin wins.
- `pa_sync_skipped_records` / `skipped ...` in `check` — records that will not be published
  (disabled, LUA/ALIAS and other non-Route53 types, NS/DS, non-authoritative).

Go live:

```bash
helm upgrade dns-sync sortns_charts/pdns-r53-sync -n dns --reuse-values --set sync.dryRun=false
kubectl -n dns logs deploy/dns-sync-pdns-r53-sync | grep 'sync reason'
# sync reason=startup ... dry_run=false changes=N applied=N, later runs changes=0
```

Edits that do not bump the SOA serial (pdnsutil, direct SQL) are picked up by the periodic sync.

## Monitoring

Pods carry `prometheus.io/scrape|port|path` annotations (`metrics.scrapeAnnotations`).
`serviceMonitor.enabled` / `prometheusRule.enabled` add Prometheus Operator objects;
`prometheusRule.metricSelector` (e.g. `namespace="dns"`) narrows the alert expressions.

| Metric | Meaning |
|---|---|
| `pa_sync_dry_run` | 1 in dry-run |
| `pa_sync_source_serial` / `pa_sync_synced_serial` | serial in Poweradmin / of the last good sync |
| `pa_sync_last_success_timestamp_seconds` | last successful sync |
| `pa_sync_syncs_total{reason,result}` | reason: startup/serial/periodic/retry; result: success/error/unsafe/guard |
| `pa_sync_poll_errors_total` | failed serial polls |
| `pa_sync_planned_changes{action}` | create/update/delete in the latest plan |
| `pa_sync_applied_changes_total` | changes written to Route53 |
| `pa_sync_unsafe_plans_total` | plans refused by thresholds |
| `pa_sync_hosted_zone_check_ok` | hosted zone guard state |
| `pa_sync_skipped_records{type,reason}` | records not published |

Alerts: `PdnsR53SyncStale`, `PdnsR53SyncPoweradminUnreachable`, `PdnsR53SyncUnsafePlan`,
`PdnsR53SyncHostedZoneGuard`.

## Notes

- **Hand over ownership before going live.** If the records are managed by Terraform (or anything
  else) today, stop managing them there first (`terraform state rm` / `removed {}` blocks for the
  `aws_route53_record`s), otherwise Terraform and the sync revert each other. Records that stay
  Route53-only (aliases, ACM validation) can stay in Terraform; the sync ignores them.
- Mirrored types: A, AAAA, CAA, CNAME, MX, NAPTR, PTR, SPF, SRV, SSHFP, TLSA, TXT. TLSA and SSHFP
  are added on top of octodns-route53, which does not map them yet. Other types (HTTPS, SVCB, LUA,
  ALIAS, ...) are reported as `skipped ... (unsupported)` and are neither published nor touched in
  Route53.
- ACME clients that write `_acme-challenge` TXT records straight into Route53 need
  `filters.rejectNames: ["/^_acme-challenge/"]`, or the periodic sync may delete a challenge in flight.
- TXT values with `;` are written to Route53 in escaped form (`\;`, RFC 1035), which resolvers
  receive as plain `;`. After going live, check one record:
  `dig +short TXT _dmarc.example.com @<one of the awsdns servers>`.
- Route53's default SOA has minimum 86400 s and TTL 900 s, so NXDOMAIN answers are cached for up to
  15 min. Lowering that is a manual one-off change of the SOA record in Route53; the sync never
  touches SOA.
- NetworkPolicy (`networkPolicy.enabled`) only matters with a CNI that enforces it; egress needs
  DNS and TCP/443 to Poweradmin and AWS.
